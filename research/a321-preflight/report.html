1. 연구의 목표와 완료 정의

목표는 A321 G1B Blender 모델을 출발점으로 저속 외부유동 한 조건을 계산하고 압력·유선·후류·양력·항력을 읽는 전체 절차를 재현하는 것이다. 현재 단계의 완료는 유동 계산이 아니라 입력 정의, 원본 보존, 형상 진단, 후보 작성, STL 독립 재검사다. 표면 폐합이 곧 항공기 공력 정확도를 뜻하지 않는다.

첫 계산 제안은 30 m/s, 288.15 K, 밀도 1.225 kg/m³, 동점성계수 1.46e-5 m²/s, 받음각 2°, 옆미끄럼 0°, 중력 없음이다. 이는 연구 가정이며 실제 A321 운항·풍동 조건의 재현이 아니다. 형상이 통과하기 전까지 계산 입력으로 채택하지 않는다. 기체 길이 44.51 m를 사용한 길이 Reynolds 수는 약 9.15e7이다. 이를 주익 시위 Reynolds 수와 혼동하지 않는다. 실제 주익 시위·기준 면적·모멘트 기준점은 아직 잠그지 않았다.

이번 시험 형상은 엔진·파일런·랜딩기어·내부·장식 이음선·일부 슬롯·두께 없는 스포일러 판을 제외한 airframe-only 시도다. 정상적인 clean A321 형상이라고 이름 붙이지 않는다. 플랩·슬랫 자세, 접합, 개구부가 아직 수용되지 않았기 때문이다. 엔진·기어 생략은 계산 편의상의 모델링 가정이며 성능 손실을 무시할 근거가 아니다.

3.1 정량 표면 검사

각 방향 12,000개 결정적 정점 표본과 실제 삼각형 BVH 최단거리를 사용했다. 연속 Hausdorff 상한이 아니다. 전체 정점의 배열 순서 표본은 큰 부품 편중을 일으킨다. 따라서 40 mm 시험에서는 55개 부품 각각도 따로 검사했다. 최대 표본거리는 좌·우 wing-body fairing 약 0.7681 m, Belly 약 0.3525 m, sharklet 약 0.2833 m, Crown 약 0.2222 m다. 이 결과가 전역 0.3128 m보다 커서 전역 표본만으로 승인하지 않았다.

0.15 m 예비 예산은 큰 형상 손실을 찾아내는 연구용 탈락 기준이다. 제조 허용오차나 공력 정확도 허용값이 아니며, 후속 날개 앞전·뒷전·두께·비틀림 수용 기준은 별도로 훨씬 구체적으로 설정해야 한다. 현재 두 시험은 이 느슨한 예비 기준도 통과하지 못했다.

실제 삼각형 교차선 6단면을 sections.svg에 기록했다. X=5,20,35 m와 Y=5,10,15 m를 사용했다. 동체 외피의 틈과 날개 뒷전 형상 손실이 보인다. coplanar 삼각형은 그리지 않으므로 그림은 폐합 판정의 대체물이 아니다.

3.3 하위체계 후보의 의미

artifacts/wing-subsystem/wing-fixed-box.blend와 .stl은 우측 고정 날개 상자 한 부품이다. 면적은 전체 젖은 표면적 89.324369 m², 부호 체적 16.299853 m³이며, 이 면적을 CL/CD용 주익 평면 기준 면적으로 사용하면 안 된다. 스팬 방향 범위는 Y=0~16.29 m다. 슬랫·플랩·에일러론·샤클렛·동체·엔진/파일런은 포함하지 않는다. 따라서 나중에 계산해도 “A321 양력·항력”이 아닌 격리된 고정 주익 부품의 탐색 계산이다.

새 Blender 프로세스에서 다시 열어 같은 정점/면/적분값을 확인하고 STL을 재출력했다. 왕복 SHA는 artifact manifest에서 비교한다. 자기교차·접촉·곡률 정확성·OEM 단면 동일성은 아직 UNMEASURED다. 제한 위상 PASS를 mesh-ready 또는 engineering GO로 승격하지 않는다.

5. 항공기 검토 순서와 후속 수용 기준

  1. 정체성: 기종·모델 개정·원본 SHA·파생 과정과 생략 부품을 고정한다. 다른 후보를 이름이 비슷하다는 이유로 섞지 않는다.
  2. 좌표·치수: native는 X 뒤쪽, Y 우현+, Z 위. GLB의 Y-up 좌표와 혼동하지 않는다. 길이·스팬뿐 아니라 station별 단면, 날개 두께·앞전 반경·뒷전·비틀림·좌우 비대칭을 점검한다.
  3. 유동 공간: 내부 표면·중첩 껍질·밀폐 공극·유로 연결을 구분한다. 실제 틈을 수치 편의로 닫았으면 별도 형상으로 기록한다.
  4. 위상: 열린 변, 비다양체, 접촉, 자기교차, 뒤집힘, 퇴화·중복, 분리 성분을 검사한다. 정확 좌표 검사와 허용오차 용접 검사를 혼동하지 않는다.
  5. 형상 충실도: 수리 전후 위치·단면·곡률·젖은 면적·분리 성분을 비교한다. 복셀 크기가 항공기 뒷전·슬롯보다 크면 소실 위험을 판정한다.
  6. 격자: 기하 세분화와 유동 격자 세분화는 다른 오차원이다. 비직교·skewness·양 체적·폐합·유체 연결·첫 셀·경계층 확보율·앞전/익단/후류 포착을 검사한다.
  7. 물리 모델: 저마하 적용 범위, 난류·천이·표면 거칠기·자유류 난류량·엔진 조건·지면 효과를 목적에 맞게 정의한다.
  8. 계산 수렴: 잔차·질량 불균형·힘의 안정성·NaN·역류·압력 기준을 함께 기록한다. 정상해의 지속 진동은 잔차 숫자를 줄여 숨기지 않는다.
  9. 불확실성: 격자 3수준과 영역 크기·모델·시간간격 민감도를 분리하고, 같은 형상/조건의 실험값이 없으면 NOT_VALIDATED를 유지한다.

30 m/s·alpha=2° 계획의 바람 축은 d=(cosα,0,sinα), 양력 축은 l=(-sinα,0,cosα)로 정의한다. 합력 F는 기체 벽 압력+점성 힘 벡터에서 읽어 D=F·d, L=F·l로 계산한다. CL=L/(0.5ρV²Sref), CD=D/(0.5ρV²Sref)에서 Sref는 날개 평면 기준으로 따로 측정·고정한다. 현재 wall-force 출력의 면적·질량가중 평균 속도·평판 마찰 추정을 자유류 기준으로 쓰지 않는다.

rust/src/bin/lowmach.rs 3246줄 부근은 힘 벡터를 출력하고, rust/src/wallfunctions.rs의 pressure_force는 운동학적 p에 경계 밀도를 곱한다. 코드의 기본 drag axis가 유입 방향을 자동으로 의미하지 않는 경우가 있어 전체 벡터를 재투영한다. 피칭 모멘트·반복별 힘 이력·단면별 Cp는 별도 측정 경로 보완이 필요할 수 있다. 이번에는 솔버 코드를 바꾸지 않았다.

7. 현재 불가능·미확인 항목과 다음 한 건

  • 전기체 격자 투입: FIX_FIRST. 자동 복셀 후보의 형상 손실·성분 분열·퇴화가 실제 확인됨.
  • A321 정확 CL/CD·실속·이착륙·순항 성능: 미계산·미검증. 저마하 솔버로 순항 천음속 충격파를 다룰 수 없음.
  • 전체 모델 자기교차·접촉 전수검사: UNMEASURED. BVH 최단거리와 변 incidence는 자기교차 완전 검사를 대체하지 않음.
  • 실행 환경: 이전 조사에서 CUDA 12.6만 확인, 문서는 13.x 요구, ofgpu 실행 파일 없음. 이번 범위에서는 설치/빌드/probe 안 함.
  • GPU 두 장의 VRAM 합산: 지원하지 않음. 한 장 16GB 안에서 추후 측정해야 함. 허용 셀 수·시간은 미측정.
  • Studio GUI: 이전 턴에서 React maximum update depth 오류 관측. 이번에는 수치 계산과 별개로 보존하며 수리/완주를 주장하지 않음. CLI/MCP 경로는 별도.
  • Blender GUI 도구: 연구용 주익 사본은 별도 실행했지만 Computer Use helper가 창 목록 조회에서 시간 초과. 실제 GUI 검토 PASS로 기록하지 않음. CLI 별도 재열기 근거만 사용.

다음 한 건: 전기체 동체 Crown/Belly를 3~5개 station으로 나눠 외피/안쪽 return/창·문 개구를 구분하고, 허용된 작은 국소 수리만으로 폐합할 수 있는지 CPU에서 검토한다. 우측 고정부는 단순 기준 문제용 후보로 보존하되 전기체 실패를 대신 통과시키지 않는다. 표면 수용 전 정점 link·자기교차·접촉 전수 검사를 추가해야 한다.

8. 재실행과 산출물 안내

실행 명령은 RUNBOOK_KO.md, 기계용 계획은 study.json, 정확 파일 목록은 evidence/artifact-manifest.json, 자동 결과는 evidence/를 따른다. artifacts/는 Git에 포함되지 않으므로 이 작업트리를 제거하기 전에 바이너리와 SHA 목록을 함께 보존해야 한다. 이번에는 push·PR·발행·기본 모델 갱신을 수행하지 않는다.

독립 검토에서 재실행 출력 경계와 정점 다양체 검사 범위 표기를 보완했다. custody.py는 연구 evidence/artifacts 밖의 출력, 동결 입력, 기존 결과 덮어쓰기를 거부한다. 새 trial 폴더만 생성한다. 이 경계는 실수 방지이며 악의적인 동시 파일 교체를 막는 OS 보안 샌드박스는 아니다. 증거 생성 당시 어댑터와 보강 후 어댑터의 차이는 유한좌표 거부·출력 경계·검사 범위 metadata이고, 원 형상 수치 알고리즘은 유지했다. 이전 자동 증거 JSON에는 새 metadata가 없으므로 이 문서와 함께 읽는다.

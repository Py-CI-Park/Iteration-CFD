# 세 방향 독립 진단

원본 R3와 이전 결과를 읽기 전용으로 조사했다. 외부 라이브러리 구현 소스는 읽지 않았다.

## A. Windows Netgen 입력 경계

Netgen 6.2.2608의 작은 tetra STL 대조에서 float 좌표 바이트에 0x1A 또는 CRLF를 넣으면 binary 입력은 degenerated 진단과 0점/0면을 냈지만, 동일 좌표를 ASCII로 전달하면 14점/24면을 만들었다. 평범한 binary tetra도 성공했다. 따라서 모든 binary STL이 불가능한 것이 아니라 **특정 바이트에 민감한 Windows loader 문제**가 관찰됐다. Windows text-mode 처리가 원인이라는 설명은 이 대조에서 강하게 지지되는 추론이다. 구현 내부 단계는 확인하지 않았다.

R3 파일은 129,522 삼각형·6,476,184바이트, 유한 좌표·비영 면적이며 SHA가 일치한다. 파일에 0x1A 13,677개와 CRLF 3쌍이 있다. R3를 바꾸는 대신 좌표 왕복을 검사한 별도 ASCII 복사본을 외부 도구에 전달한다. native mesher가 빈 결과를 반환해도 종료 코드 0일 수 있으므로 출력 mesh도 검사한다.

## B. TetGen 접합 경계

이전 quality-exterior-02/03 raw 출력은 배열까지 동일했다. 정점 45401과 52585는 삭제되거나 다른 원래 정점에 병합된 것이 아니라 **같은 인덱스를 유지한 채** 각각 18.7890046µm, 12.3580872µm 이동했다. 각 정점의 다섯 boundary triangle과 전체 aircraft boundary 129,522개는 입력과 동일했다. 다른 원래 정점과의 거리는 각각 6.14639mm, 5.01102mm 이상이었다.

이 두 좌표를 메모리에서 복구했을 때 영향받는 사면체는 25개·21개였고, 비양수 determinant나 부호 변경은 없었다. 복구 후 최소 det(6V)는 4.82298e-8 및 3.82817e-8m³였다. 이는 검사 없이 원래 좌표로 덮어써도 된다는 뜻이 아니다. 각 후보에서 전체 접합·체적·비직교·폐합을 재검사해야 한다.

## C. 품질 불변식

이전 최악 tet–tet 면 352795는 셀 중심의 법선 방향 간격 0.737254mm에 비해 접선 방향 간격이 5.766929m여서 89.992675°다. Tet의 정점 평균은 실제 체적 중심이므로 centroid 공식만 바꿔 해결할 수 없다.

나쁜 prism–prism 면 214,088개 중 214,027개는 층 사이가 아닌 옆면이다. 최악 쌍의 바닥 삼각형 최소각은 0.313303°/0.304575°, 전체 표면 최소각은 0.002787°였다. 해당 두 프리즘의 층 두께를 1→0.1→0.01배로 줄여도 비직교각은 89.916881°→89.917690°→89.917770°로 개선되지 않았다. 따라서 무조건 두께를 줄이는 대신 계산 표면 분할 자체와 외부 grading을 함께 바꾼다.

대조 hex/polyhedral 경로가 통과하더라도 사면체 경로의 성공으로 부르지 않는다. 상대 폐합 정의 |ΣSf|/|V|^(2/3) 및 1e-10 기준은 그대로 유지한다.

질문의 답: 직접 어디까지 해결할 수 있는가

Blender 외형 재생성, 형상 검사, CPU 격자 생성·개선 반복, Studio 확인, 해석 입력 준비, 실행 환경 구성, 조건부 GPU 시험과 결과 정리까지 직접 수행할 수 있다. 이 작업은 실제 CLI·앱 API·Ego Lite·파일 검증으로 진행한다.

다만 모든 격자가 반드시 합격하거나 계산이 반드시 수렴하며 실제 A321 공력과 일치한다고 미리 보장할 수는 없다. 그런 판정은 실제 형상·격자·엔진·유동 검증 결과로 결정한다. 현재 자료만으로 OEM 익형과 실기 공력 정답을 복원할 수 있다고 주장하지 않는다.

권고안은 기존 R3/R4와 06~11을 보존하고, 별도 R5_REBUILD 외형을 처음부터 매개변수로 구성하는 것이다. 기존 10은 격자 대조군으로 남긴다. 이번 커밋은 그 실행 계획과 환경 확인이며 R5 생성·새 격자·GPU 계산은 아직 실행하지 않았다.

권고 방향: R5 외형부터 재구성

왜 계속 삼각형만 다듬지 않는가

R3/R4는 기존 단면을 연결한 삼각형 연구 셸이다. 국소 보간과 smooth shading은 일부 연결부·표시를 개선하지만 전체 곡률·표면 분할·날개 접합을 설계하는 작업과 다르다. R4에는 작은 triangle angle도 남는다. 새 R5는 설계 가능한 단면·곡선·패치 구조를 먼저 만들고, 그 뒤 계산 표면으로 삼각분할하는 방향을 우선한다.

먼저 실제 형상 굴곡과 표시상의 각짐을 구별한다. 현재 Studio 형상 미리보기에는 flat shading 경로가 있어 보이는 각짐 전부를 실제 홈으로 단정하면 안 된다. 같은 시점의 Blender flat/smooth·wireframe과 실제 단면·곡률 수치를 비교한다. 표시 문제뿐인 부분은 기하를 불필요하게 변형하지 않는다.

Blender 외형 생성의 실제 순서

  1. 기준 정의: R3/R4의 좌표·스케일·단면·투영 형상을 측정하고, 유지할 치수와 새로 허용할 연구 형상 변경을 먼저 문서화한다. 기존 convex envelope를 OEM 익형으로 취급하지 않는다.
  2. 동체: 중심선과 여러 단면을 곡선/표면 제어점으로 구성한다. 길이·폭·높이·단면 변화와 코·꼬리 형상은 수치로 비교한다.
  3. 주익: 평면형과 익형 단면을 분리해 제어한다. 앞전·뒷전 위치, chord·두께·캠버·비틀림을 기록하고, 허용된 범위에서 단면 연결 기울기와 곡률을 다듬는다.
  4. 미익: 같은 원칙으로 수평·수직미익을 구성한다. 좌우 대칭은 생성 규칙과 실제 좌표 대조로 검증한다.
  5. 접합: 날개-동체 전이의 패치를 명시적으로 설계한다. Boolean 합집합이 성공했다는 이유만으로 극소면·자기교차·나쁜 곡률이 해결됐다고 판정하지 않는다.
  6. feature 보존: 동체·익면·앞전은 의도한 매끄러움을 추구하되, 물리적으로 의도한 뒷전과 평면형 꺾임까지 무조건 둥글게 만들지 않는다. 뒷전 두께와 tip 처리도 연구 가정으로 고정한다.
  7. 계산 표면 변환: 곡률·앞전·뒷전·접합부를 고려해 삼각분할한다. 표시용 메시와 계산 입력의 차이를 기록하고, 작은 면·긴 가는 삼각형·계단을 검사한다.
  8. 독립 재읽기: Blender 저장 후 새 프로세스에서 열고, 최종 STL·native·검사 배열의 좌표 대응과 해시를 확인한다.

Blender의 곡면·mesh 변환 기능은 공식 매뉴얼을 참고한다. Blender에서 매끄럽게 보이는 것만으로 watertight CAD·전역 자기교차·공력 적합성을 통과시키지 않는다. 형상 재생성 자체와 독립 CPU 검사를 분리한다.

M3~M6의 구체적인 판정 원칙

  • 보존: 원본을 덮어쓰지 않고 각 시도의 입력·명령·코드·출력 해시를 연결한다. 실패한 후보도 원인을 기록한다.
  • 형상: 열린 edge, 비다양체 edge, 잘못된 winding, 중복/퇴화면, 분리 성분, 의도치 않은 교차를 검사한다. 전역 교차 검사를 못 하면 검사하지 않은 상태로 남긴다.
  • 형상 허용오차: 동체·앞전·뒷전·tip·접합·익형 두께/캠버 등 feature별 기준을 M1에서 정한다. 보편적인 임의 1 mm 기준이나 표본 최대값만으로 전역 보증을 만들지 않는다.
  • 격자: 양수 체적·단일 유체 연결·폐합과 방향, 독립 최대 비직교 ≤70°, 최대 상대 폐합 ≤1e-10을 유지한다. 기존 determinant/가중치 기준 및 완전한 native 확장 검사도 유지한다. 왜곡·오목 셀을 허용해 과거 실패를 PASS로 바꾸지 않는다.
  • 층: 현재 8층 요청·실제 평균·완전 8층 면·면적·첫 높이·총두께·누락/종료 위치를 구별한다. R5에서 물리 설계상 층 수를 바꿀 필요가 있으면 새 명세·새 버전으로 고정하고 기존 8층 실패 이력은 그대로 남긴다.
  • 물리: 실제 solved y+는 해석 후 확인할 값이다. 실행 전 추정/설계 y+를 실제 계산 결과처럼 기록하지 않는다.
  • 검사 완결성: 다른 case·시간의 로그, 중간 종료, fatal, 누락된 집합을 0 또는 PASS로 처리하지 않는다.
  • CPU 인수 경로: 실제 드라이버의 CPU-only 검증 지원부터 확인한다. GPU 초기화·커널이 필요한 경로를 CPU 검사라고 부르지 않으며, 해당 작업은 장치 선택·실행 gate 뒤로 분리한다.
  • 원인 분리: 형상만 바꾼 대조, 격자 조건만 바꾼 대조를 둔다. 일관된 진전이 없으면 같은 가설의 단순 parameter 조절을 무한 반복하지 않고 표면 구조·mesher/셀 전이 방식을 재검토한다.

물리와 솔버: 외형만 새로 만들면 끝나는가

끝나지 않는다. 실제 목표는 항공기 주변의 속도 U와 압력 p를 계산하는 것이다.

  1. 유동 조건: 목표 U=(30,0,0) m/s, 모델 기준 받음각 0°를 유지한다. 이것은 zero-lift 각도라는 뜻이 아니다.
  2. 물성: 기존 ρ=1.225 kg/m³·ν=1.5e-5 m²/s는 준비 가정이다. 온도·고도·물성 일관성은 물리 명세에서 확정한다.
  3. 난류/벽처리: coupled RANS와 벽처리를 우선 검토하되 특정 모델이 항상 맞다고 고정하지 않는다. 첫 높이를 키워 층이 잘 붙었다는 이유만으로 물리적으로 적합하다고 판단하지 않는다.
  4. 계수: 양력·항력 방향, 기준 면적·길이·모멘트 기준점을 고정한다. 항공기 전체 wetted 표면적을 날개 기준 면적으로 임의 사용하지 않는다.
  5. 진짜 유동 드라이버: 현재 Guidebook §6는 ofgpu-k-epsilon/k-omega/sa가 속도를 고정한 채 난류만 푼다고 명시한다. 이 셋을 항공기 전체 유동 계산으로 사용하지 않는다.
  6. 검토 후보: Guidebook에 U/p/T와 난류를 푼다고 명시된 ofgpu-lowmach를 우선 검토 대상으로 두고, 정확한 경계·물성·모델·force 기능을 실제 엔진 계약으로 확인한다. 이 경로는 T 필드도 요구하므로 U/p만 넣고 실행하지 않는다.
  7. 대안: 원하는 엔진 경로가 지원하지 않거나 기준 문제를 통과하지 못하면 GPU 준비를 중단한다. 필요한 어댑터 수정·실행 경로 검증 또는 별도 외부 CPU 기준 해석을 검토하고, 외부 CPU 실행을 Iteration GPU 성공으로 표시하지 않는다.

격자 통과, 수렴, 수치 검증, 실제 실험과의 validation은 다른 단계다. 실제 비행 성능이나 인증 수준으로 결과를 확대하지 않는다.

첫 GPU 시험 이후의 성공 기준

  • 짧은 실행은 launch 성공뿐 아니라 실제 U/p 갱신, 질량 수지·잔차·힘 이력·벽 진단이 정상인지 확인한다.
  • 반복 수렴이 느리거나 발산하면 중단 조건대로 멈춘다. 안정화하지 않은 결과를 평균값으로 숨기지 않는다.
  • 같은 형상·물리 조건에서 거친/중간/세밀 격자를 비교하고, 외부 영역 크기 민감도를 구분한다. 세 격자가 있다는 이유만으로 수렴·외삽 적용 조건이 자동 충족됐다고 판단하지 않는다.
  • 엔진 검증은 필요한 물리 모델과 가까운 공개 기준 문제를 대상으로 한다. 저장소 전체 validation의 기존 OPEN/MISSES를 사라진 것으로 간주하지 않는다.
  • 실기 A321 비교 자료가 없으면 최종 결과의 범위는 명시된 단순화 연구 항공기의 학습용 해석이다.

방법론은 사용자 제공 NASA V&V 튜토리얼, CFD Analysis Process, Spatial/Grid Convergence를 참고한다. 이번 Ego 실제 접근 기록: 출처, 방법론.

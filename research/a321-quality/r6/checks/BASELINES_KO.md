# R6 표면 게이트 스위트와 R3/R4/R5 기준선 — sonnet-r6-checks

**결론: 재사용 가능한 게이트 `r6_gate.py`(15개 시험 통과)를 만들고 R3·R4·R5-C·R5-A 9개 입력 전부에 돌렸다. 입력 SHA256은 실행 전후 9개 모두 같다. 게이트는 핸드오프가 기록한 surfaceCheck 자기교차 위치 수(R3 72, R4 86, R5-C 15, R5-A 4,184)와 최소 품질(9.70744e-13 / 1.19287e-11)을 그대로 재현했다. 반면 독립 locator는 9개 표면 모두 0쌍이고, PyMeshLab은 4개 표면(R3 합집합·R3 동체·R4·R5-A)에서만 6~20면을 선택한다. 세 검사기는 R3 주익·수평미익·수직미익 3개에서만 모두 0으로 일치하고, 나머지에서는 서로 다르다.** 이 문서는 측정값과 후보 문턱만 제시한다. 최종 문턱은 오케스트레이터가 잠근다.

## 1. 만든 것

| 파일 | 역할 |
|---|---|
| `r6_gate.py` | CLI. `--surface name=path.stl`(반복), `--features`, `--stations`, `--deviation name=ref.stl`, `--checkers`, `--log-dir`, `--out` |
| `r6_mesh.py` | STL 읽기, **값 기준 정확 용접**(-0.0과 +0.0 병합), 변 표, 성분·오일러·감김·성분별 부호 부피 |
| `r6_metrics.py` | 품질 3종, 크기 변화, 이면각, 특징선 제외, 스테이션 꺾임, bbox·부피·표본 이탈 |
| `r6_selfint.py`, `r6_meshlab_worker.py` | 세 검사기 호출·비교. PyMeshLab(GPL)은 **별도 프로세스**에서만 실행 |
| `run_surfacecheck_r6.sh` | WSL에서 새 `mktemp -d` 안에 STL **복사본**으로 surfaceCheck 실행 |
| `test_r6_gate.py` | 합성 시험 15개 |
| `run_baselines.sh`, `run_pass2.sh`, `run_followups.sh`, `assemble_baselines.py`, `print_baseline_tables.py` | 기준선 실행·병합·표 생성 |
| `baselines.json` | 9개 표면의 전 지표(분포, 개수, 교차 확인, 검사기 비교) |
| `logs/` | 표면별 실행 로그·원시 JSON·SHA 전후 기록(전부 50 MB 미만, 잘라내지 않음) |
| `attempts/` | surfaceCheck 시도 폴더(로그·OBJ·SHA; 입력 복사본은 SHA 기록 후 삭제) |

**지표 8개를 모두 구현했다.**
1. 폐합: 용접 후 경계 변, 비다양체 변, 반복 정점 면, 성분 수, 오일러 수, 성분별 genus.
2. 방향: 감김 불일치 변(각 방향 변이 정확히 한 번씩 쓰이는지)과 **성분별** 부호 부피.
3. 자기교차: (a) 기존 locator를 import로 재사용(복사·수정 없음), (b) PyMeshLab `compute_selection_by_self_intersections_per_face`, (c) surfaceCheck.
4. 삼각형 품질: Q_OF, 최소 내각, 종횡비(가장 긴 변 / 가장 짧은 높이)의 min·p0.1·p1·p5·중앙값(+p95/p99/max)과 기준선 아래 개수.
5. 크기 변화: 변을 공유하는 모든 삼각형 쌍의 면적비·최장변비.
6. 매끄러움: 이면각 분포와 10°/20°/30° 초과 변(좌표 포함 상위 20개). 스테이션 꺾임.
7. 특징선: 선택 입력 JSON(`tolerance_m` + `features[].polyline`). 제외 전·후를 함께 보고한다.
8. 형상: bbox, 부호 부피, 선택 입력 기준 표면 대비 양방향 표본 최대 이탈.

**Q_OF 정의.** `Q_OF = 4A / (3·sqrt(3)·R²)`, R은 외접원 반지름 `abc/(4A)`다. 삼각형 면적을 같은 외접원에 내접하는 정삼각형 면적으로 나눈 값이다(정삼각형 = 1, 붕괴 = 0). **surfaceCheck가 `-writeSets vtk`로 쓰는 삼각형별 `quality` 배열에 맞춰 실험적으로 찾았다.** R3 동체 46,592개 삼각형에서 비율이 1 ± 6e-8이었다(`calibrate_quality_vs_surfacecheck.py`, `logs/calibration-run.log`). 2r/R, `4√3·A/Σe²` 등 다른 후보는 맞지 않았다(비율 0.09~1.33). OpenFOAM 소스는 읽지 않았다. 이전 C15 문서의 `Qeq`와 `Qradius`는 surfaceCheck 품질과 다른 양이라는 점도 이 맞춤으로 확인된다.

**교차 확인(공짜 검증).** 9개 표면 모두에서 게이트의 용접 정점 수와 삼각형 수가 surfaceCheck가 읽은 값과 같고, 성분 수가 "unconnected parts"와 같으며, surfaceCheck의 `closed` 판정이 게이트의 watertight와 같다. 최소 품질의 값은 상대 오차 1.7e-6 이내(surfaceCheck가 float32로 읽는 차이)이고 삼각형 번호도 R3 수평미익 하나를 빼고 같다(12767 대 12769; 두 값이 6자리까지 같아 float 잡음으로 순서가 바뀐 것으로 본다).

## 2. 기준선 측정(원시 지표)

입력은 `baseline_inputs.txt`의 9개다. R3 합집합은 `models/`와 `artifacts/shell-r3/`에 두 사본이 있으며 **저장된 법선 필드만 다르고 정점 데이터는 비트까지 같다**(SHA는 다르다). 모든 지표가 같으므로 아래 표는 `models/` 사본만 싣는다. `baselines.json`에는 두 사본이 모두 있다.

스테이션 꺾임의 R3 부품 표본은 `reconstruction-r3.json`의 `parts[].axis`/`stations_m`을 쓴다(동체 x, 주익·수평미익 |y|, 수직미익 z). **합집합·R4·R5처럼 부품이 합쳐진 표면은 각 부품의 bounds 안이면서 다른 부품 bounds 밖인 변만 쓴다.** 겹치는 영역의 변은 버리므로 근사값이다.

특징선은 이 기준선에서 **실제 R6 특징선이 아니라 시연용**이다. R3 저장 단면 링의 x 극값(앞전 최소 x, 뒷전 최대 x)으로 만든 10개 폴리라인이며 허용오차 2 mm다(`make_features_r3.py`, `features_r3_ring_derived.json`). 링은 방사 표본이라 실제 모서리와 정확히 같지 않다. 날개 끝·접합 루프·꼬리 끝 등은 포함하지 않았으므로 "특징선 제외" 열은 설계 계약이 아닌 기능 시연이다.

## 3. 세 자기교차 검사기의 일치와 불일치

**범위가 다르다.** (a) locator는 정점을 하나라도 정확히 공유하는 쌍을 아예 제외하고 면 쌍을 센다. (b) PyMeshLab은 용접된 메시에서 교차에 걸린 **면**을 고른다. (c) surfaceCheck는 **위치**를 센다. 그래서 개수 차이를 곧바로 "거짓 양성"으로 읽지 않는다. 원인은 확정하지 못했다.

| 구분 | 표면 | 관찰 |
|---|---|---|
| 세 검사기 모두 0 | R3 주익, 수평미익, 수직미익 | 일치 |
| locator 0, surfaceCheck > 0 | R3 합집합 72, R3 동체 255, R4 86, R5-C 15, R5-A 4,184 | **5개 표면에서 불일치** (R5-C, R5-A는 기존 독립 스캔·지도와 같은 결론) |
| PyMeshLab > 0, surfaceCheck > 0 | R3 합집합(6면), R3 동체(6면), R4(6면), R5-A(20면) | 면과 점은 거의 겹치지 않는다. surfaceCheck 점이 PyMeshLab 면 100 µm 안에 든 수: 2/72, 0/255, 2/86, 6/4,184 |
| PyMeshLab 0, surfaceCheck > 0 | R5-C 15 | 불일치 |
| locator 0, PyMeshLab > 0 | 위 4개 표면 | locator가 비어 있어 비교할 면이 없다 |

- **R5-C 15, R5-A 4,184, R4 86, R3 합집합 72는 핸드오프 기록과 정확히 같다.** 이번 실행으로 재현됐다. R3 동체 단독 255는 새 측정이다.
- **PyMeshLab이 고른 면 하나를 자세히 봤다.** R3 합집합의 12516번과 12550번은 같은 평면(법선 내적 1.0000000000000002, 서로 반대편 정점의 평면 거리 5e-21 이하)에 있고 최소 정점 간 거리가 0.106 m이다. locator의 `intersection_points`는 빈 결과를 낸다. 두 삼각형은 겹치지 않는다. 즉 이 쌍에서는 PyMeshLab이 공면이지만 겹치지 않는 삼각형을 교차로 표시했다. **다른 PyMeshLab 면은 이렇게까지 검사하지 않았다.**
- **surfaceCheck 점의 위치.** 동체 바닥(z < 2.03)과 윗면(z > 6.08)에 몰리는 정도는 표면마다 다르다. R5-C는 15개 중 14개, R3 합집합은 72개 중 12개, R4는 86개 중 13개, R5-A는 4,184개 중 622개, R3 동체는 255개 중 48개다. R5-C 밖에서는 대부분이 다른 곳이다. 이 분포만으로 원인을 말하지 않는다.
- **저품질 삼각형과의 관계.** surfaceCheck 점이 Q_OF < 0.01 삼각형 100 µm 안에 든 수는 R3 합집합 0/72, R3 동체 0/255, R4 0/86, R5-C 2/15, R5-A 0/4,184다. 위치와 낮은 품질은 거의 겹치지 않는다.
- **locator의 한계.** 모든 표면에서 0이므로 이 locator는 "정점 공유 쌍을 제외한 실제 관통"이 없다는 증거이고, surfaceCheck의 접촉형 보고와는 다른 대상을 본다. 그래서 R6 판정은 locator 하나로 하지 않는다. 판정 문턱 후보는 §5에 둔다.

## 6. 정확한 명령(모두 새 로그 파일에 남음)

# 입력 SHA 전·후

surfaceCheck 실행(WSL): `source /usr/share/openfoam/etc/bashrc; surfaceCheck -checkSelfIntersection -outputThreshold <0|100> input.stl`을 새 `mktemp -d` 폴더 안의 복사본에서 실행했다. 원본 경로에는 쓰지 않았고, 복사본 SHA가 원본과 같음을 매번 기록했다. `-writeSets`는 품질식 맞춤용 R3 동체 1회에만 썼다.

## 7. 하지 않은 것과 불확실한 점

- R6 후보가 없으므로 R6 판정은 하지 않았다. 문턱은 제안일 뿐이다.
- 실제 R6 특징선(날개 끝, 앞전·뒷전, 접합 루프, 꼬리 끝)은 정의하지 않았다. 시연용 폴리라인은 링 극값 근사이며 계약이 아니다. "특징선 제외" 숫자는 기능 시연이다.
- 합집합·R4·R5의 스테이션 꺾임은 bounds 기준 근사다. 구조화 격자가 아니면 B 집합이 비거나 평균이 0.01° 아래라 비율이 정의되지 않는다(R3 부품은 모든 정점이 스테이션 위라 B가 비어 있다).
- 표본 이탈은 표면당 20,000점 양방향(고정 seed 20261116)의 **최댓값**으로 진짜 Hausdorff 거리의 하한이다.
- surfaceCheck 내부의 교차 판정 방식과 허용오차는 알아내지 못했다(소스를 읽지 않음). PyMeshLab도 면 하나만 정밀 확인했다.
- 대조된 이면각 큰 변(> 30°)의 위치와 원인은 이번 범위가 아니라 좌표 상위 20개만 `baselines.json`에 있다.
- locator는 float64 술어이며 정확한 유리수 증명이 아니다(기존 설명과 같다).
- 개발 중 스모크 시험 surfaceCheck 한 번(`attempts/sc-r3_vertical-Vu16qe`)이 남아 있다.
- 금지 사항 준수: Blender, 메셔, CFD 솔버, GPU, `ofgpu-*`를 쓰지 않았다. 대화형 프로그램도 쓰지 않았다. 기존 파일은 수정하지 않았고 쓴 곳은 `research/a321-quality/r6/checks/`뿐이다.

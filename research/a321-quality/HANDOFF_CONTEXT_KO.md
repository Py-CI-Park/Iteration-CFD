## 실행의 의미를 쉽게 설명

```text
항공기 외형 = 바람이 만나는 겉껍데기
표면 mesh   = 껍데기를 작은 삼각형으로 나눈 것
체적 mesh   = 주변 공기를 작은 방으로 나눈 것
경계층      = 껍데기 가까운 얇은 방들을 물리에 맞게 쌓는 것
형상 검사   = 껍데기가 새거나 자기 자신을 뚫는지 확인
격자 검사   = 작은 방이 뒤집히거나 지나치게 찌그러졌는지 확인
solver      = 그 방들에서 속도·압력 등을 계산
validation  = 계산 결과가 비교 실험/정답과 맞는지 확인
```

Blender에서 예쁘게 보임 → 표면 합격 → 격자 합격 → 해석기 지원 → 계산 수렴 → 현실 검증은 각각 다른 사건이다. 현재는 C 껍데기의 교차15위치를 해결하고 feature/면품질을 확인해야 하는 지점이다.

## 수행할 수 있는 범위와 미확정 범위

직접 수행 가능한 작업은 Blender 코드 모델링·STL/native 검사·CPU mesher·불량지도·엔진 adapter/host-only 경로 구현·빌드 준비·Ego 실제화면·문서/Git, 그리고 선행gate 후 승인된GPU시험이다. AI API가 없어도 결정적 스크립트로 연구를 진행할 수 있다.

현재 데이터만으로 OEM A321의 실제 익형·구조·항력 정답을 복원하거나 모든 후보가 반드시 합격한다고 약속할 수 없다. CFD “처음 한 번”의 목표도 물성·경계층·격자·엔진·수렴 확인을 생략할 근거는 아니다.

## 다음 연구자의 표현 규칙

- `PASS_SCOPED`: 해당 검사 범위만 통과. 공학 전체합격으로 확장하지 않는다.
- `FAIL`: 실제 측정이 기준에 못 미침. 실패 파일을 보존한다.
- `PENDING / UNMEASURED`: 검사하지 않았거나 증거가 없음. 0개/실패/성공으로 대체하지 않는다.
- `HOLD`: 선행gate 때문에 항공기GPU를 시작하지 않는다.
- `NOT_RUN`: 실제 해석을 실행하지 않음. 화면·memory복사·reader로 대체하지 않는다.
- `RESEARCH_SNAPSHOT`: 재개용WIP보존. release나물리승인아님.

문서의 옛 숫자·시간·그림은 출처시점과 같이 인계하고 현재실행으로 재활용하지 않는다. 매 단계 무엇이 완료됐고 왜 다음 단계가 막혔으며 어떤 검사를 통과해야 하는지 쉽게 설명한다.

3. 누적 사용자 의도·승인

원래 목표는 Aircraft-Workbench의 A321 Blender 모델을 참고해 항공기 공력 해석을 한 번 직접 경험하는 것이다. Ego Lite·컴퓨터 유즈·Chrome·CLI를 활용하고, 모델부터 격자·실행 환경·첫 시험·문서·Git까지 에이전트가 직접 진행하도록 요청했다.

  • R3 원본과 이전 실패 결과를 보존한다. 공력용 새 겉껍데기와 Blender 외형 재생성은 허용됐다.
  • 매끄러운 표시만 바꾸지 말고 홈/단면/접합과 실제 기하를 확인한다.
  • 저속 외부유동 **30 m/s·기준 받음각 0°**를 첫 목표로 사용자가 선택했다.
  • 기존 비직교·폐합·양수 체적·확장 품질·경계층 조건을 낮춰 합격시키지 않는다.
  • GPU 메모리 테스트는 승인됐지만 품질 통과 전 항공기 GPU 해석 금지는 계속 유효하다.

이번에는 실패 R5-A STL/BLEND/NPZ, B 실행코드/입력원장, C raw STL/NPZ/실행코드/입력원장, C presentation STL/native를 명시적으로 Git에 수록한다. 일반 artifacts ignore 규칙을 전체 해제하지 않는다. 실행 중간 cache·fixture·locks는 원격 복제 필수 자산과 구분한다. A/C 실패 모델도 입력·검사 재개를 위해 보존할 가치가 있으며 계산용 accepted 모델은 아니다.

기존 snappy/processor/대형 NPZ·mesh는 계속 로컬에 있고 이번에 원격 전체 업로드하지 않는다. 다른 컴퓨터에서 예전 격자를 그대로 열려면 해당 artifacts를 별도 복사하고 기존 manifest로 검증하거나, 보존된 입력·도구 버전·새 output 경로로 재생성해야 한다. 새clone에 원시 격자가 전부 있다고 가정하면 안 된다.

정확한 파일 SHA/크기/전달 범위는 핵심 자산 manifest, 로컬 보존 폴더, 전체 연구 파일 색인을 따른다. manifest는 relative path로 제공하므로 checkout 루트가 달라도 검증할 수 있다. 원시 영수증 안의 당시 절대경로는 감사 이력으로 남긴다.

이식성 검사에서 기존 Git의 R3 단면 원장만 LF로 정규화되고 로컬 M1 동결본은 CRLF인 차이를 발견했다. 이번에는 로컬 입력 바이트를 바꾸지 않고, 해당 파일 하나의 Git 속성을 raw 보존으로 지정해 동결 SHA가 새 clone에서도 유지되도록 기록했다. STL/native나 JSON 데이터 값 변경이 아니다. 과거 commit을 재작성하지 않으며, 기준 Git blob과 새 보존 blob이 다른 이유·줄바꿈만의 차이 증명은 입력 보존 보완에 둔다. rebuild의 원시 영수증·실행 snapshot도 같은 바이트 보존 규칙을 적용했다.
